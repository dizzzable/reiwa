# Reiwa v0.9.7.16

Продолжение вчерашнего разбора: кабинет отдавал `500` на части запросов, а живые потоки событий обрывались пачками. Причина оказалась не в коде, а в умолчании зависимости. Парная версия панели не менялась — **[Rezeis Admin v0.9.7.20](https://github.com/dizzzable/rezeis/releases/tag/v0.9.7.20)**, обновлять её не нужно.

> **Нажимать в интерфейсе ничего не надо.** Достаточно обновить образ.

## 🔌 HTTP/2 к панели никто не включал

В журнале кабинета:

```
HeadersTimeoutError: HTTP/2: "headers timeout after 10000"
  at ClientHttp2Stream.onTimeout (undici/lib/dispatcher/client-h2.js)
```

а через двадцать семь секунд — **четыре потока событий завершились в одну миллисекунду**, каждому около 106 минут.

Одно испорченное соединение унесло с собой все запросы в полёте и все живые потоки разом.

**Транспорт сменился сам.** В настройках соединения с панелью HTTP/2 не запрашивался никогда: библиотека `undici` включает его по умолчанию, и это приехало с обновлением зависимости. Вместе с транспортом молча изменился смысл настройки «пятьдесят соединений»: она выбиралась под пятьдесят **независимых** соединений, где отказ одного стоит одного запроса. При мультиплексировании всё едет по одному TCP-соединению, и цена отказа становится общей.

Теперь протокол задан **явно**. Не потому, что HTTP/2 плох — а потому, что умолчание, переписывающее модель отказов, не должно меняться без того, чтобы кто-то отредактировал строку. Для посредника, который веером шлёт короткие вызовы поверх приватного канала, изоляция отказов важнее экономии на рукопожатиях.

## 🧵 Потоки событий получили свои соединения

Поток, живущий полтора часа, и вызов, живущий двадцать миллисекунд, больше не делят бюджет соединений. Что бы ни случилось с одной группой, вторая продолжает работать.

Побочно это закрывает соседнюю ловушку: отсутствие ограничения на время чтения тела — то, что делает поток потоком, — раньше жило в общем месте и могло достаться обычным запросам, которым нужен конечный срок.

Завершение работы теперь закрывает оба набора соединений: иначе процесс не останавливался по сигналу столько, сколько подписчик держит вкладку открытой.


**Мутацией: 4 из 4.** Вернуть умолчание протокола; вернуть потоки в общий пул; дать потокам ограниченное время чтения; забыть про закрытие второго набора соединений — каждая правка роняет свой именованный тест.

Вторая проверка появилась потому, что в собственных тестах нашлась дыра: проверки настроек **не заметили бы** отмену разделения — там меняется одно слово, а все утверждения остаются зелёными. Теперь у этого отдельный сторож, и он же следит, чтобы третий набор соединений, добавленный когда-нибудь позже, не унаследовал умолчание молча.
