# Reiwa v0.9.7.43

Патч по сообщениям тестировщика. Главное:

- кнопка добавления подписки в Telegram Desktop открывает приложение;
- обязательная подписка на канал при запуске бота снова проверяется;
- токен бота больше не пишется в логи и не уходит в отчёты об ошибках;
- уведомления через бота не теряются молча при сбоях Telegram, а отказ Telegram доходит до оператора.

⚠️ **Выпускается в паре с Rezeis Admin v0.9.7.58. Сначала панель, потом кабинет.** Новый кабинет со старой панелью (0.9.7.57): каждый пост рассылки в канал и каждая копия уведомления в чат оператора, которые Telegram отклонил, дают отдельное оповещение «не доставлено» и упавшую задачу, а паузу, которую просит Telegram, старая панель не соблюдает. Новая панель со старым кабинетом работает безопасно.

⚠️ **Миграций и новых переменных окружения нет, compose менять не нужно.**

## 📌 Коротко

- 📱 **Подключение:** внутри любого клиента Telegram кнопка ведёт через страницу вне мини-приложения — и в Desktop на Windows тоже. Если скрипт с telegram.org не загрузился, внешние ссылки мини-приложения открывает сам клиент Telegram.
- 📢 **Канал обязателен:** проверка работает, когда «ID канала» пустой. Если проверить нельзя, оператор узнаёт об этом, а не получает молча пропущенных.
- 🔐 **Логи:** токен бота вырезается из любой строки лога и из отчётов об ошибках, которые кабинет шлёт в панель.
- 🤖 **Доставка:** сбой отправки повторяется, а не записывается как «доставлено»; отказ Telegram приходит оператору с причиной; пост рассылки в канал теперь правится и отзывается из панели.

## ✅ Что сделать после обновления

- [ ] **📢 Если включён «Канал обязателен»:** в Telegram добавьте бота в канал **администратором** (права не нужны). Без этого Telegram не отдаёт боту список подписчиков, и проверка пропускает всех — теперь с оповещением: событие `reiwa.error` в «Журнал аудита» → «Системные события» и карточка в группе администраторов, если она настроена в «Уведомления» → «Настройки доставки». Текст начинается с `Channel gate cannot check subscriptions` (Telegram отказал) или `Channel gate is on but checks nobody` (в настройках нет канала, который можно проверить).
- [ ] **📢 Для закрытого канала** (ссылка вида `t.me/+…`): в панели «Платформа» → карточка «Настройки платформы» → «ID канала» (`-100…`) → «Сохранить настройки платформы». По одной ссылке-приглашению проверить нельзя.
- [ ] **📢 Проверяете отпиской?** Посмотрите «Платформа» → карточка «Брендинг» → «Перепроверять подписку». Когда переключатель выключен, прошедшего проверку бот сутки (или до своего перезапуска) не проверяет на /start повторно — отписка в это время /start не закроет. Подсказка под переключателем («проверка только при первом входе») неточна: повторная проверка всё-таки бывает, раз в сутки. «✅ Я подписался» проверяет всегда.
- [ ] **🔐 Токен бота.** До этой версии сетевой сбой запроса к Telegram (обрыв или сброс соединения, сбой TLS, ответ 5xx не в JSON) писал токен в лог бота, а отчёт об ошибке мог унести его в панель. Найдите в «Журнал аудита» → «Системные события» события `reiwa.error` с текстом вида `bot123456:`. Если токен нашёлся там или логи контейнера бота уходили во внешнюю систему, перевыпустите токен у @BotFather (`/revoke`) и сохраните новый в панели.

## 📱 «Кнопка добавления подписки в Telegram Desktop ничего не делает»

**Где:** кабинет → «Подключить» на карточке подписки → приложение → кнопка добавления подписки.

**Как было.** В 0.9.7.42 для Telegram Desktop на Windows оставили прямую ссылку со схемой приложения (`happ://…`). Встроенный браузер Telegram Desktop пропускает только http, https и ton, поэтому нажатие молча отменялось. Если скрипт Telegram с telegram.org не загрузился, внешние ссылки открывались через `window.open`, а внутри мини-приложения это ненадёжно.

**Как стало.**

- Внутри любого клиента Telegram кнопка открывает страницу подключения вне мини-приложения. Обычно это системный браузер; на Android может открыться встроенный браузер Telegram, в Telegram Web — новая вкладка. На странице нужно нажать «Открыть приложение», и уже она открывает приложение.
- Если скрипт Telegram не загрузился, кабинет передаёт ссылку клиенту напрямую. Telegram Desktop на Windows и macOS, Android и iOS получают её через мост клиента. Telegram Web (web.telegram.org, webk.telegram.org, weba.telegram.org) и Telegram Desktop на Linux — через окно Telegram Web. Подписанная ссылка уходит только клиенту Telegram.
- Тем же путём теперь открываются и другие внешние ссылки мини-приложения: кнопка оплаты на странице возврата после оплаты, «Подключить» при выключенном экране подключения, внешние кнопки подсказок и экрана подключения.
- Ссылки на t.me, telegram.me и telegram.dog идут прежним путём.

**⛔ Не проверено на устройстве.** Ни один клиент не проверен вживую: Telegram Desktop на Windows, macOS и Linux, путь без скрипта Telegram на Android и iOS, Telegram Web K/A. Всё проверено тестами в эмуляции браузера по исходникам клиентов. Ссылку на t.me без скрипта Telegram Desktop открывает, сначала закрыв мини-приложение, — ожидание оплаты на странице возврата при этом прерывается.

## 📢 «Проверка подписки на канал при запуске бота не работает»

**Где:** панель → «Платформа». Карточка «Настройки платформы»: «Канал обязателен», «Ссылка на канал», «ID канала». Карточка «Брендинг»: «Username канала», «Перепроверять подписку». У подписчика — /start и «✅ Я подписался».

**Как было.** Пустой «ID канала» панель передаёт как `null`, а бот принимал его за заданный канал — и не смотрел ни username, ни ссылку. Проверка считалась выключенной: все сразу попадали в меню. Если бот не был администратором канала, Telegram отказывал, а отказ молча читался как «подписан». Участник с ограничениями, уже вышедший из канала, считался подписанным.

**Как стало.**

- Канал берётся из любого из трёх полей: `-100…`, `@name`, `name`, `https://t.me/name`. Кнопка «вступить» получает полную ссылку `https://t.me/name`; ссылка-приглашение остаётся как есть.
- Подписка проверяется на /start и по «✅ Я подписался».
- Если проверить нельзя, подписчик **проходит** — платящего человека проверка не запирает. Оператор получает оповещение не чаще раза в час на причину, если причина на его стороне: Telegram отказал (бот не администратор, неверный ID или username, бота удалили из канала) или в настройках нет канала, который можно проверить. Если недоступен сам Telegram, запись появляется только в логе бота.
- Счётчик «раз в час» и память о прошедших проверку живут в процессе бота: после перезапуска оповещение может прийти снова.

**⛔ Что НЕ сработает.** Проверка стоит только на /start и «✅ Я подписался». Её обходят: мини-приложение и кабинет, открытые напрямую; кнопки в меню, присланном раньше; ссылки заданий и возврата после оплаты.

## 🔐 «Токен бота виден в логах»

**Как было.** Когда запрос к Telegram падал на уровне сети, ошибка содержала адрес запроса вместе с токеном, и логгер печатал её целиком. Туда же попадали текст сообщения подписчика и байты отправляемого файла. Отчёты об ошибках, которые кабинет шлёт в панель, тоже уходили без очистки.

**Как стало.** Токен в виде `bot<id>:<секрет>` вырезается из каждой строки лога — в любом поле и в тексте сообщения — и из текста и стека отчётов об ошибках. Текст сообщения и файл запроса в лог не попадают; тип и код ошибки, метод и ответ Telegram остаются.

## 🤖 Доставка уведомлений через бота

- **Сбой отправки** (обрыв соединения, 5xx, сбой TLS) — бот просит панель повторить. Раньше карточка оператора и документ рассылки в канал при таком сбое записывались доставленными, а уведомление подписчику молча считалось недоставленным без настоящего повтора. Редкий дубль возможен, если Telegram успел принять сообщение.
- **Отказ Telegram** — шаблон, который Telegram не разбирает или который слишком длинный; группа или топик, из которых бота удалили, — теперь приходит в панель с причиной, и панель 0.9.7.58 даёт одно оповещение на причину. Раньше такие отказы проходили молча.
- **Подписчик, который ни разу не запускал бота** (`chat not found`), — тихий окончательный ответ без оповещения. В рассылке такие строки сразу становятся недоставленными и больше не останавливают рассылку по импортированной базе после пяти подряд.
- **Пауза, которую просит Telegram** (429), доходит до панели. Очередь пересылки повторяет не раньше конца паузы (плюс секунда) и не раньше своей обычной задержки; пауза длиннее 15 минут урезается до 15. Рассылка подписчикам паузу не читает и повторяет пакет по своему расписанию.
- **Пост рассылки в канал** теперь сообщает панели номер сообщения. Правка и отзыв отправленной рассылки доходят и до поста в канале — вместо «…в канале остался старый — поправьте пост вручную». Только для постов, отправленных после обновления.
- **Ошибки развёртывания видны.** Если у reiwa-api и reiwa-bot разный `REZEIS_INTERNAL_SHARED_SECRET`, панель получает ошибку, повторяет и оповещает — раньше кабинет молча отвечал «принято». Если доставка в группу администраторов не настроена («Уведомления» → «Настройки доставки» → «Включить доставку в Telegram» и «Chat ID») и у бота не задан `BOT_DEV_ID`, каждая карточка, которую панель шлёт на запасной адрес разработчика, даёт предупреждение в логе reiwa-api.
- **Баннер, скачивание которого оборвалось на середине**, больше не ломает /start, экраны бота и уведомление — они уходят без баннера.
- **Ответ бота кабинету оборвался по дороге** после доставленного уведомления или поста в канал — повтор отвечает сохранённым номером сообщения, без второй копии, если бот не перезапускался между попытками.
- **Отметку «подписчик заблокировал бота»** бот ждёт не дольше 2 секунд. Если панель отвечает медленнее, такая строка рассылки может попасть в «Повторить для N недоставленных».

## 🧪 Чем проверено

Перед выпуском по обоим репозиториям прошли независимые проверяющие агенты, затем две волны исправлений, и каждое исправление отдельно проверял ревьюер. Каждое исправление закрыто тестом, который падает на старом коде, и доказано нарочной поломкой: исправление убирают — тест обязан покраснеть. Заметки к выпуску сверены с полным диффом и с названиями в интерфейсе панели, бота и кабинета.

- **Кабинет:** 4435 тестов в 341 файле и 29 тестов свойств; проверка типов сервера, тестов и браузерной части, обе сборки — чисто.
- **Токен в логах:** 16 тестов на настоящих ошибках grammY — обрыв соединения, сброс, HTML-ответ 502, отказ Telegram, отправка файла, отчёт в панель, сбой запуска. Каждый краснеет, если вырезание убрать.
- **Проверка канала:** настоящий бот grammY против локального сервера в роли Bot API — неподписчик, подписавшийся, вышедший участник с ограничениями, «бот не администратор», одна ссылка-приглашение.
- **Кнопка в Telegram Desktop:** связь без скрипта Telegram — все три адреса Telegram Web, родительское окно, скрывающее свой адрес, и чужое окно, которому ссылка не уходит.
- **Сквозной стенд:** 17 сценариев из 17 на образах панели и кабинета, собранных из этого кода.
