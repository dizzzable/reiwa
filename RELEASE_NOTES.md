# Reiwa v0.9.6.58

🎬 **Анимация удаления подписки наконец доигрывает** — карточка растворялась ~465 мс из заложенных 5000 и просто исчезала. Заодно регистрация перестала наказывать за опечатки, а пробная подписка — обещать то, что сервер откажет. Панель: **rezeis v0.9.6.72**.

### ✨ Что нового
- **Регистрация терпима к ошибкам** — 5 попыток в час на IP (было фактически 2: заявленные 3 отказывали уже на третьей). Попытки, которые ничего не создали — невалидные данные, занятый логин, закрытая регистрация — в бюджет не идут вообще. Лимит ограничивает аккаунты, а не опечатки: за одним IP у мобильного оператора сидят тысячи абонентов.
- **Отказ в пробной подписке называет причину** — уже использована, уже есть активная подписка, тариф только по оплате, только по приглашению, временно недоступна. ru + en.

### 🐞 Исправлено
- **Анимация удаления жила ~9% отведённого времени.** Realtime-событие `subscription.deleted` (дебаунс 400 мс) обновляло список, он приходил пустым, и дашборд менял карусель на пустой экран — размонтируя её вместе с механизмом, который должен был удержать карточку. Теперь ветка держится, пока анимация не доиграет. Замерено на собранном билде: **4904 мс, 15 частиц, карточка ни разу не уходит из кадра** — проверено и с одной подпиской, и с двумя.
- **Восстановление пароля блокировало IP на сутки на всех эндпоинтах.** Три попытки — и человек терял вход, регистрацию и поддержку на 24 часа, вместе со всеми, кто делит с ним адрес. Теперь это обычная блокировка восстановления до конца окна.
- **Пробный оффер исчезал молча.** При отказе блок пропадал прямо посреди спиннера без единого слова — причина теперь уходит в уведомление, которое переживает исчезновение блока.
- **Устаревший кэш пригодности пробной подписки.** Он не сбрасывался нигде: активировал триал, удалил подписку — и в течение минуты оффер предлагался снова. Теперь обновляется после активации, после удаления подписки и по realtime-событию. Это наиболее вероятная причина исходной жалобы «блок показан после удаления пробной».
- **Триал, выданный вне кабинета** (бот, админка, награда за квест), не появлялся на дашборде до перезагрузки — событие не обновляло тот список, который читает карусель.
- **Отказ по нераспознанной причине** больше не оставляет в кэше «пригоден»: пригодность перечитывается на любом отказе.
- Два теста рекламного API переведены на один общий сервер — редкие падения полного прогона («Worker exited unexpectedly») ушли.

### 🔒 Безопасность
- **Возврат попытки не распространяется на 5xx.** Регистрация отвечает `500 «аккаунт создан, сессия не поднялась»` уже после создания аккаунта — возврат в этом случае отдавал бы слот за реальный аккаунт и снимал лимит именно в момент аварии.
- **Возврат не может попасть в следующее окно.** TTL сверяется с зафиксированным на инкременте: окно, начавшееся позже нашего, не примет возврат, иначе запрос, ответивший сразу после смены часа, покупал бы лишние регистрации.
- **Занятый логин (409) возврату подлежит** — осознанно: `POST /auth/check-username` отвечает на тот же вопрос и вообще вне этого лимитера, так что плата за 409 не давала защиты от перебора, а слот у живого пользователя забирала.

### ✅ Гейты
- **561 pass** (79 файлов) + **29 property-тестов**, typecheck ✅, build ✅
- Кабинет: `tsc -b` ✅, build ✅
- Изменения проверены роем из семи адверсариальных ревьюеров по срезам (анимация, лимиты, пробная подписка, i18n, тесты, соседний код, готовность к выпуску); найденные блокеры устранены до выпуска.

### ⚠️ После обновления
- **Порядок деплоя любой**, новых полей в запросах нет. Предпочтительно rezeis первым — чтобы причина отказа по лимиту заявок уже существовала. Миграций, новых переменных окружения и правок compose нет.
- **Действующие баны IP сохраняются.** Записи `banned_ip:*`, созданные 0.9.6.57, продолжают блокировать до 24 часов: новый код их уважает, но новых по восстановлению не создаёт. Для немедленного эффекта — почистить `banned_ip:*` в Redis.
- **Удаление подписки теперь занимает ~5 секунд** до исчезновения карточки. Так задумано; при `prefers-reduced-motion` — 160 мс, как и раньше.
- **Осталось открытым, честно:** перебор логинов метрируется только общим лимитом 120/мин на `POST /auth/check-username` — если нужно, ограничим отдельно. И спам восстановления теперь 2/час на IP без бана; чтобы защитить конкретный аккаунт от рассылки, нужен лимит на целевой логин, а не на адрес.

# Reiwa v0.9.6.57

🎯 **Переходы по рекламе наконец фиксируются** — ссылка объявления, открытая в браузере, теперь считается переходом и привязывает регистрацию к размещению, включая вход через Google / Яндекс / Telegram. utm-метки доезжают вместе с ней. Панель: **rezeis v0.9.6.71**.

### ✨ Что нового
- **Серверный захват рекламной ссылки** — `?campaign=ad_<код>` перехватывается на входе: переход учитывается сразу, код паркуется в httpOnly-cookie на 7 дней, а из адресной строки убирается. Кабинет больше не может потерять код при внутреннем редиректе.
- **utm-метки записываются** — `utm_source` / `utm_medium` / `utm_campaign` / `utm_content` / `utm_creative` (и `utm_term` как псевдоним креатива) уходят вместе с переходом и попадают в разрез в панели.
- **Привязка при входе через соцсети** — регистрация кнопкой Google / Яндекс / Telegram теперь тоже привязывается к размещению, а не только форма с паролем.
- **Статус размещения в партнёрском кабинете** — плашка «трекинг выключен» и комментарий оператора по заявке вместо молчаливой смены статуса.

### 🐞 Исправлено
- **Рекламные веб-ссылки не фиксировались вообще** — код размещения приезжал только в адресной строке, а первый же переход кабинета (`/` → `/sign-in` → `/register`) стирал query до появления сессии. В кабинете по такой ссылке не появлялось ни переходов, ни регистраций, ни меток.
- **Метки терялись даже когда доезжали** — параметры не читались ни на входе, ни при отправке, поэтому разрез по utm в панели физически не мог заполниться.
- **Аналитический запрос выкидывал из кабинета** — просроченная сессия на фоновом `/advertising/click` уводила пользователя на страницу входа прямо с дашборда.
- **Одноразовый токен магической ссылки протаскивался дальше** по переходам входа: теперь через них переносится только то, что нужно (utm, `ref`, `next`).
- **Повторная отправка привязки больше не глушится навсегда** — флаг «уже отправлено» ставился до ответа сервера, и одна сетевая ошибка отключала атрибуцию на всю вкладку. Теперь есть ограниченные повторы, а код хранится до подтверждения.
- **Партнёру раздавались ссылки и QR для размещения на паузе**, клики по которым молча выбрасывались.

### 🔒 Безопасность
- **Открытия не накручиваются подресурсами** — картинка или скрипт с рекламным параметром больше не считается переходом и не подсаживает cookie атрибуции; добавлен лимит записи на источник.
- **Строгий редирект захвата** — цель всегда остаётся на своём домене (проверено на absolute-form и обратных слэшах).
- **Известный вектор подписи внутренних запросов** закреплён тестом: панель теперь эту подпись проверяет, и расхождение схем сломает тест, а не прод.

### ✅ Гейты
- **561 pass**, typecheck ✅ (backend + кабинет), build ✅
- Проверено четырьмя роями адверсариальных ревьюеров; предрелизный рой дал fix-first, все блокеры устранены до выпуска.

### ⚠️ После обновления
- **Выкатывать после панели.** Кабинет отправляет новое поле `attributeOnly`, старая панель ответит на него 400 и привязка потеряется безвозвратно.
- Ссылка объявления теперь **отвечает редиректом** и убирает `?campaign=` из адресной строки — так и задумано, код уже сохранён на сервере.
- Проверять переход **в новом приватном окне**: повторное открытие той же ссылки в том же браузере намеренно не считается новым переходом.
